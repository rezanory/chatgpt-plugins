# Recover Kaggle Campaign Incidents

Recover the smallest affected lane without widening authority, repeating compute, or admitting ambiguous evidence.

Read [references/incident-patterns.md](references/incident-patterns.md) when classifying logs or a 403. Read [references/recovery-contract.md](references/recovery-contract.md) before retrying, superseding, cancelling, or resuming an interrupted chat. When logs are available, run `scripts/triage_incident.py` first; its output is diagnostic and never authorizes a mutation.

## Core contract

- Reconcile the canonical repository, branch, commit SHA, tree/blob hashes, campaign, lane, account, kernel reference, workflow run, and durable receipts before changing anything.
- Inspect the live ChatGPT/Codex conversation as well as GitHub and Kaggle state. A transport failure is not proof that execution stopped.
- Start with read-only status, log, identity, and quota probes. Use a unique request ID and preserve the exact receipt.
- Distinguish source/contract bugs from account credentials, OIDC admission policy, event delivery, runner/network infrastructure, and stale metadata.
- Never replay a compute or write request until its previous run and provider-side effect have been reconciled. Quarantine a duplicate rather than merging its outputs.
- Treat immutable candidates as immutable. A source correction requires a minimal superseding candidate, fresh hashes, and the full applicable validation.
- Preserve scientific and governance fences. Recovery does not unlock later phases, fan-in, release gates, or locked-test evaluation.

## Decision sequence

1. **Detect:** Capture the exact visible error, live chat state, GitHub run and job IDs, provider status, and current canonical SHA.
2. **Classify:** Use the narrowest supported pattern from the incident reference. Unknown or incomplete evidence remains fail-closed.
3. **Isolate:** Freeze the affected lane and keep independent lanes running when their dependency and authority contracts permit it.
4. **Reconcile or fix forward:** Repair identity, policy, transport, or infrastructure first when source mutation is not proven necessary. For a proven source defect, create a superseding candidate; do not amend the frozen predecessor.
5. **Revalidate:** Check exact bytes/hashes, focused behavior, the complete required gate set, provider acceptance, and observable resumed progress.
6. **Record:** Publish a secret-free incident record containing classification, subreason, scope, exact evidence links, unblock condition, next action, duplicate disposition, and authority fences.

## Non-obvious protections

### Fresh Kaggle persistence

Treat a missing fresh persistence artifact as confirmed absence only for either an actual HTTP 404 or KaggleHub's exact `BackendError` JSON envelope with all of these fields:

- `wasSuccessful` is exactly `false`;
- `error.code` is integer `5`;
- `errors` is exactly `["Not found"]`.

Permission errors, malformed payloads, different codes/messages, network failures, and generic exceptions remain failures. Test positive and negative cases before launching a successor.

### Exact byte identity

For notebooks, manifests, archives, and other hash-bound payloads, serialize once to bytes and use byte-preserving writes such as `Path.write_bytes(...)`. Do not depend on platform text-newline conversion. Compare the generated bytes with the expected Git blob or manifest hash on the actual runner before any provider write.

### OIDC and account readiness

An HTTP 403 from an aggregate readiness workflow does not prove a bad Kaggle credential. Reconcile deployed OIDC `workflow_ref`, event, branch/ref, actor, and the Git history of trust entries first. Do not re-authorize a temporary workflow whose trust was intentionally removed after onboarding. Probe accounts through the permanent allowlisted read path, with bounded concurrency and one durable result per account.

### Interrupted chats and duplicate launches

Resume the same stable conversation from the exact unfinished point only after reconciling its side effects. If overlapping recovery created two campaigns, choose the canonical one from exact source/evidence identity, quarantine the other from selection and fan-in, and cancel only when an exact provider session ID and cancellation authority are proven.

## Completion evidence

Do not declare recovery from a plan or a green-looking focused check. Require the affected lane to resume observable progress or reach its expected terminal state, exact provider and Git identities to match, every required validation to be accounted for, duplicates to be fenced, and later scientific phases to remain unchanged unless separately authorized.
